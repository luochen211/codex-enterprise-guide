项目定位

不是命令速查表，而是一套 Codex 工作方法。

这个项目会围绕真实任务组织内容：个人如何起步，开发者如何进入仓库，团队如何建立规范、权限边界、验收标准和复盘机制。

学习路线

四阶段，从会用到可交付。

01

入门闭环

安装、登录、理解入口，完成第一个低风险任务。

02

工程实践

读仓库、改文件、跑测试、解释 diff 和剩余风险。

03

工作流扩展

接入 MCP、Skills、浏览器、文档、PPT 与自动化任务。

04

团队沉淀

建立 AGENTS.md、权限策略、任务模板、案例库与复盘制度。

内容体系

先搭骨架，再一节节长出来。

入口地图

CLI、桌面 App、Cloud、IDE、ChatGPT 分别适合什么场景。

配置专题

config.toml、沙盒、审批、网络、凭据、项目规则和安全边界。

任务设计

把模糊需求写成 Codex 能稳定执行、可验证、可交付的任务。

团队 Playbook

把成功经验沉淀为模板、流程、检查清单和贡献规范。

服务器部署

从静态托管、云服务器、Nginx 到域名、HTTPS、日志和备份。

CI/CD 流水线

用自动检查、构建、预览环境和生产发布，让每次改动都有闭环。

服务器与 CI/CD

项目要能被访问，也要能被稳定更新。

企业级项目不是写完页面就结束。我们会补一条完整发布链路：本地开发、代码提交、自动检查、构建产物、服务器部署、回滚和监控。

Server

服务器介绍

说明静态托管、云服务器、Docker、Nginx、HTTPS、域名解析和访问日志分别解决什么问题。

Pipeline

CI/CD 介绍

每次 push 后自动执行格式检查、构建、基础测试，并把通过的版本发布到预览或生产环境。

Operate

上线后维护

记录部署版本、回滚入口、错误日志、备份策略和权限边界，避免项目上线后失控。

实战案例

每个案例都要能复现、能迁移、能验收。

案例库会从真实工作流出发，不只写“能做什么”，还要写清楚输入、过程、验证、风险和适用边界。

  • Codex 改造一个前端项目
  • 用 AGENTS.md 约束团队代码风格
  • 让 Codex 修复 GitHub Actions 失败
  • 用 Playwright 验证页面交互
  • 把重复交付流程做成 Skill
  • 为非开发团队搭建资料整理工作流
