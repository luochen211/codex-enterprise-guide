# 共建指南

这个项目适合用小步方式共建。

优先贡献真实案例、明确教程和可验证流程。少写泛泛观点，多写可以复现的步骤。

## 内容原则

### 写给具体的人

每篇内容先明确读者：

- 第一次使用 Codex 的新手。
- 已经会写代码但不会让 Codex 进项目的开发者。
- 想把 Codex 引入团队流程的负责人。
- 想做自动化交付的创作者。

### 写成可执行流程

好的教程应该包含：

- 前置条件。
- 操作步骤。
- 命令或配置。
- 预期结果。
- 常见失败。
- 验证方式。

### 写出边界

不要只写“推荐这样做”。要说明什么时候适合，什么时候不适合。

## 提交流程

1. 新建分支。
2. 修改 `docs/` 下的文档。
3. 本地运行 `npm run build`。
4. 提交 PR。
5. 等待 GitHub Actions 通过。

## 文档风格

- 标题直接说主题。
- 段落短一点。
- 命令必须可复制。
- 风险和前提要写清楚。
- 真实失败比空泛成功更有价值。
