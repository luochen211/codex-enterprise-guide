# 案例库

这里不收“最后成功了”的漂亮总结，只收能看见现场、误判、证据和修正过程的真实任务。

如果你还不熟悉 GitHub 的仓库、分支、PR、分支保护和 worktree，建议先读 [GitHub 协作基础](/guide/github-workflow)，再看下面的事故案例。

读一个案例时，重点看七件事：

- 背景是什么。
- 输入材料是什么。
- 给 Codex 的任务怎么写。
- Codex 做了哪些动作。
- 怎么验证结果。
- 哪些地方失败过。
- 这个案例适合迁移到什么场景。

## 写案例时怎么组织

先还原事情怎么发生，再列出当时掌握的证据。接着写做过哪些判断、哪些判断后来被推翻、最终怎样验收。最后只保留能迁移到下一次任务的规则，不要补写当时并不存在的动机和结果。
