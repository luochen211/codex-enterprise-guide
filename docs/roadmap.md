# 学习路线

这条路线按照“从会用到可交付”设计。

## 01 入门闭环

目标：完成第一个低风险任务，并知道怎样判断结果是否可信。

你需要掌握：

- Codex 的不同入口：CLI、IDE、Cloud、ChatGPT。
- 如何描述任务背景、目标、约束和验收标准。
- 如何让 Codex 先读项目，再动手修改。
- 如何阅读它给出的 diff、测试结果和风险说明。

产出物：

- 一个成功执行的小任务。
- 一份任务提示词模板。
- 一条“修改后必须验证”的习惯。

## 02 工程实践

目标：让 Codex 进入真实仓库，并完成可交付改动。

你需要掌握：

- 项目结构识别。
- 依赖安装与本地运行。
- 小步提交与变更说明。
- 测试、构建、lint 和页面检查。

产出物：

- 一个可运行的本地项目。
- 一个通过构建的 commit。
- 一份验证记录。

## 03 工作流扩展

目标：让 Codex 不只写代码，也能参与文档、浏览器、设计稿、自动化和发布。

你需要掌握：

- Skills 的使用与沉淀。
- MCP 工具接入。
- Playwright 页面验证。
- GitHub Actions 排障。
- 文档站、PPT、流程图等交付物生成。

产出物：

- 一个团队可复用的任务流程。
- 一个自动化检查或发布流程。
- 一个可复现案例。

## 04 团队沉淀

目标：把个人经验变成团队资产。

你需要掌握：

- `AGENTS.md` 项目规则。
- 权限、沙盒与审批策略。
- 代码 review 与验收清单。
- 失败案例复盘。
- 团队贡献规范。

产出物：

- 团队 Playbook。
- 案例库。
- CI/CD 发布规范。
