# 学习路径

这条路径不按工具多少来分级，而按你能不能完成一次真实交付来分级。每往前走一步，都要留下能检查、能复用的结果。

![Codex 学习路径：从会用到可交付](/learning-path.png)

## 路径总览

| 阶段 | 你要解决的问题 | 建议先读 |
| --- | --- | --- |
| 00 基础认知 | 先判断项目是什么，别一上来就写代码 | [产品形态](/guide/product-forms)、[技术栈](/guide/tech-stack)、[对 AI 友好的代码](/guide/ai-friendly-code) |
| 01 入门闭环 | 完成第一个低风险任务，并知道怎么验收 | [项目总览](/guide/overview) |
| 02 工程实践 | 进入真实仓库，完成可提交的改动 | [GitHub 协作基础](/guide/github-workflow)、[对 AI 友好的代码](/guide/ai-friendly-code) |
| 03 工作流扩展 | 让 Codex 参与验证、文档、发布和排障 | [服务器部署](/delivery/server)、[CI/CD 流水线](/delivery/cicd) |
| 04 团队沉淀 | 把个人经验变成团队规范和案例库 | [案例库](/cases/)、[共建指南](/contribute) |

推荐顺序：

```text
产品形态 -> 技术栈 -> GitHub 协作基础 -> AI 友好代码 -> 第一个任务闭环 -> 真实项目交付 -> 部署与 CI/CD -> 团队规范
```

只看懂不算完成。能复用、能验证、能交给别人接着做，才算走完一个阶段。

## 00 基础认知

目标：先把“要做什么产品、由哪些部分组成、这次交付到哪里”为止说清楚。

你需要掌握：

- 官网、落地页、Web 应用、小程序、移动 App、管理后台、API 服务和自动化工具的区别。
- 不同产品形态对应的用户入口、技术结构、部署方式和验收标准。
- 前端、后端、数据库、存储、部署、CI/CD 等技术栈层次分别解决什么问题。
- 对 AI 友好的代码原则：高内聚、低耦合、单一职责。
- 如何在给 Codex 分配任务前说明产品形态、目标用户、核心场景和交付边界。

产出物：

- 一份产品形态判断表。
- 一份项目技术栈说明。
- 一段能放进任务提示词里的项目背景描述。
- 一个清楚的交付边界：本次做什么，暂时不做什么。

## 01 入门闭环

目标：完成第一个低风险任务，并能说清它为什么算完成。

你需要掌握：

- Codex 的不同入口：CLI、IDE、Cloud、ChatGPT。
- 如何描述任务背景、目标、约束和验收标准。
- 如何让 Codex 先读项目，再动手修改。
- 如何阅读它给出的 diff、测试结果和风险说明。

产出物：

- 一个成功执行的小任务。
- 一份任务提示词模板。
- 一条“修改后必须验证”的习惯。

## 02 工程实践

目标：让 Codex 进入真实仓库，完成一项可以提交、可以验证的改动。

你需要掌握：

- 项目结构识别。
- 依赖安装与本地运行。
- 小步提交与变更说明。
- 测试、构建、lint 和页面检查。

产出物：

- 一个可运行的本地项目。
- 一个通过构建的 commit。
- 一份验证记录。

## 03 工作流扩展

目标：让 Codex 从“修改文件”走到“参与检查、发布和排障”。

你需要掌握：

- Skills 的使用与沉淀。
- MCP 工具接入。
- Playwright 页面验证。
- GitHub Actions 排障。
- 文档站、PPT、流程图等交付物生成。

产出物：

- 一个团队可复用的任务流程。
- 一个自动化检查或发布流程。
- 一个可复现案例。

## 04 团队沉淀

目标：把个人记得住的做法，变成团队都能照着执行的规则。

你需要掌握：

- `AGENTS.md` 项目规则。
- 权限、沙盒与审批策略。
- 代码 review 与验收清单。
- 失败案例复盘。
- 团队贡献规范。

产出物：

- 团队 Playbook。
- 案例库。
- CI/CD 发布规范。
